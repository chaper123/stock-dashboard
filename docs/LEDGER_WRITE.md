# 網站記帳：Apps Script 寫入服務

2026-11-05 使用者提出、同日核准設計（PROGRESS 第 11 項）。網站「記帳」頁（`site/js/pages/record.js`）把一筆台股成交寫進共用帳本，並更新「持倉」；也可以改每月定投金額（下個月生效）。

## 架構

- 寫入服務是綁在「投資共用帳本」試算表上的 Google Apps Script 網頁應用程式，程式在 `apps_script/ledger_write.gs`（repo 只放程式，不放網址與密鑰）。
- 網站用 `text/plain` 的 POST 送 JSON（簡單請求，不會有 CORS 預檢）；回應會轉址到 `script.googleusercontent.com`，瀏覽器自動跟過去。
- 寫入密鑰：Apps Script 的指令碼屬性 `WRITE_KEY`＋使用者瀏覽器的 localStorage（`ledger.writeKey`）。不放試算表（帳本是公開發布的）、不進 git、不放網址參數。網址也只存在 localStorage（`ledger.writeUrl`），網站只接受 `https://script.google.com/macros/s/…/exec`。
- 密鑰錯 10 次暫停 10 分鐘；同一個請求編號 6 小時內重送會回傳上次的結果，不會重複寫入；寫入時用 LockService 排隊。重送與確認的細節見下面「重送與確認結果」。
- 先「檢查這筆」（`dryRun`，Apps Script 照帳本最新資料試算、不寫入），再「確認寫入」。
- 網站讀帳本用「發布到網路」的 CSV，寫入後約 5 分鐘才看得到。

## 重送與確認結果（2026-11-07，改進報告 R02 的最小修補）

Apps Script（`doPost`）：
- 只有正式寫入（`addTrade`、`setMonthly`，不是 `dryRun`、不是 `ping`）才查重。快取 `req:<編號>` 存 `{ v: 2, hash, out }`：`hash` 是這筆請求內容（action＋data，鍵排序後序列化，不含 `dryRun`）的 SHA-256。
- 鎖外先查一次快取（快速路徑），**取得鎖之後再查一次**：兩個相同請求同時到、都在鎖外查不到時，先拿到鎖的寫入，後拿到的在鎖內查到結果，不會再寫。
- 同一個編號、內容相同：回傳原結果並標 `repeated: true`。內容不同（或換了動作）：回 `{ ok: false, conflict: true, error: "這個請求編號 6 小時內已經寫入另一筆內容不同的資料，這次沒有寫入。…" }`，不寫入。
- 這次沒處理到這筆的錯誤（密鑰錯、密鑰錯太多次暫停中、還沒設 `WRITE_KEY`、帳本正在寫入別的資料）標 `retry: true`，表示修好後可以用同一個編號再送；內容檢查失敗不標，也不進快取。
- 更新部署前存的舊格式快取（沒有 `hash`）照舊回傳 `repeated`，最多 6 小時後就不會再出現。

網站（`site/js/ledger_write.js`、`site/js/pages/record.js`）：
- 按「確認寫入帳本」時，**送出前**先把 `{ id, data, at, url }`（請求編號、成交內容、送出時間、目標 Apps Script 網址）存進這台裝置的 localStorage `ledger.pendingTrade`。**不存寫入密鑰。**
- 結果分三種：成功 → 清掉；Apps Script 明確拒絕（內容不對、同編號不同內容）→ 清掉並顯示原因；逾時、連線中斷、HTTP 錯誤、回應不是 JSON → 不知道有沒有寫入，保留。
- 有保留的那筆時（包括重開記帳頁），「記一筆成交」上方顯示「上次送出的這筆還沒確認結果」，有兩個按鈕：「用原編號確認寫入結果」（同一個編號、同一份內容再送一次：已經寫入就回傳原結果、不會重複寫；還沒寫入就這次寫入）和「放棄」（只刪掉這台裝置上的紀錄，帳本不動）。處理完之前「檢查這筆」不能按，避免重新填一筆變成兩筆。
- 確認時遇到 `retry` 類的錯誤（密鑰錯、帳本忙碌）或還是不知道結果：紀錄留著，可以再按。
- 送出超過 5 小時（Apps Script 的重複保護是 6 小時）就不再重送，請使用者先到帳本「交易紀錄」找這筆：有就「放棄」，沒有就「放棄」後重新填一筆。
- 紀錄的網址和目前的記帳連線不同（例如當時連的是測試帳本）時不能確認，只能改回原網址或放棄。
- 每月定投金額沒有保存未確認的請求：重送同一個金額會被「已經是這個金額」擋下，不會多一列。

新網站與舊 Apps Script、舊網站與新 Apps Script 都可以一起用（請求格式沒變），兩邊可以分開部署。只更新網站、還沒更新 Apps Script 時：鎖內查重、內容雜湊、`retry` 標記都還沒有；這時確認上次那筆遇到「密鑰不對」「帳本正在寫入」會被當成明確失敗而清掉本機紀錄。

### 已知限制（第 B 批再做）

- **部分寫入**：`addTrade` 先在「交易紀錄」加一列，再更新「持倉」。如果中間出錯（回「寫入失敗：…」），帳本可能只寫了交易列、持倉沒更新。看到「寫入失敗」請到試算表核對「交易紀錄」最後一列與「持倉」該檔的股數（「股數差異」欄）。改成以交易流水為準、持倉可重算，或有明確恢復程序的寫法，是第 B 批。
- **請求紀錄只在 CacheService**：最多 6 小時，而且是盡力保存，可能提早被清掉；被清掉後同編號重送會再寫一次。持久化的請求紀錄（處理狀態、內容雜湊、結果）是第 B 批。
- 未確認的那筆只記在送出的那台裝置與瀏覽器（例如手機送出、電腦看不到），一次只記一筆。
- 兩個相同請求同時到的情況只在本機假服務上測過（鎖的行為照 Apps Script 文件模擬），沒有在真的 Apps Script 上做併發測試。

## 本機測試（不連 Google、不碰帳本）

`tests/apps_script/` 有兩頁，用假的 `SpreadsheetApp`、`LockService`、`CacheService`、`PropertiesService`、`ContentService`、`Utilities` 原封不動跑 `apps_script/ledger_write.gs`（`fake_gas.js`）：

- `ledger_write_test.html`：自動測試，頁面標題會顯示 `PASS n/n`。涵蓋同編號連送兩次只寫一筆、兩個請求都在鎖外查不到後依序取得鎖只寫一筆、同編號不同內容（含換動作、鎖內才發現）被拒絕、`dryRun` 不查重不寫快取、`setMonthly` 重送、舊快取格式、鎖被占用回 `retry`、密鑰錯與內容錯、`ping`；網站部分測 localStorage 只存編號／內容／時間／網址（沒有密鑰）、壞掉的紀錄、回應遺失後用原編號重送只寫一筆、錯誤分類。網址加 `?src=/tmp/ledger_write.old.gs` 可以拿舊版對照（先 `git show <舊版>:apps_script/ledger_write.gs > tmp/ledger_write.old.gs`；`tmp/` 不進 git）：2026-11-07 修補前的版本在競態與同編號不同內容幾項會失敗。
- `record_sandbox.html`：記帳頁沙盒。網站的 `record.js` 原樣渲染，`fetch` 換成假的（Apps Script 網址交給假服務、帳本 CSV 由假帳本產生、其他網址一律擋掉），可以選「下一次正式寫入：回應遺失／沒送到」，按「模擬重開記帳頁」「把上次送出時間改成 6 小時前」看確認框。

執行：在 repo 根目錄開靜態伺服器（要能讀到 `apps_script/` 與 `site/`），例如

```powershell
py -3.14 -m http.server 8767 --bind 127.0.0.1 --directory .
```

再開 `http://localhost:8767/tests/apps_script/ledger_write_test.html`。測試頁只在 localhost 的 localStorage 放假網址與假密鑰，測完還原；沙盒會留下假網址與假密鑰（只在 `localhost:8767`，和正式網站分開）。

## 用測試帳本驗證（使用者做，正式部署前）

本機測試用的是假服務。上正式帳本前，先用帳本的副本實際跑一次。

### 建立測試帳本

1. 開「投資共用帳本」→「檔案」→「建立副本」→ 名稱改成「投資共用帳本（測試）」→ **不要**勾「與相同使用者共用」→「建立副本」。綁在帳本上的 Apps Script 專案會一起複製；**部署作業不會複製**，所以副本一開始沒有網址，不會動到正式帳本。
2. 在副本開「擴充功能」→「Apps Script」，把左邊 `程式碼.gs` 全選刪掉，貼上這個分支的 `apps_script/ledger_write.gs` → 儲存。
3. 換一組測試用的密鑰（不要和正式的一樣，免得網址貼錯也能寫進去）：本機預覽的記帳頁 →「⚙ 記帳連線」→「產生密鑰」複製；副本的 Apps Script →「專案設定」→「指令碼屬性」→ `WRITE_KEY` 改成（或新增成）這組 → 儲存。
4. 副本的 Apps Script →「部署」→「新增部署作業」→ 網頁應用程式、執行身分「我」、誰可以存取「所有人」→「部署」→ 授權（同第一次設定的第 6 步）→ 複製網頁應用程式網址。
5. 本機預覽網站（`.claude/launch.json` 的 `site`，或 `py -3.14 -m http.server 8765 --directory site`）→ 開 `http://localhost:8765/#/record` →「⚙ 記帳連線」貼上測試網址與測試密鑰 →「儲存並測試」，**一定要看到「✓ 連線成功：『投資共用帳本（測試）』」**，名稱不是測試帳本就停下來。localhost 的記帳連線和正式網站（GitHub Pages）是分開儲存的，不會影響手機或正式網站的設定。

注意：本機記帳頁上方的「本月已買」等數字讀的仍是正式帳本的發布 CSV（只讀）；「檢查這筆」的試算與寫入都在測試帳本。

### 手動驗證步驟（都在測試帳本）

1. **試算不寫入**：填一筆買進 →「檢查這筆」→ 測試帳本「交易紀錄」列數不變。
2. **正常寫入**：「確認寫入帳本」→ 出現「✓ 已寫入交易紀錄第 N 列」，測試帳本多一列、「持倉」股數與總成本更新。
3. **回應遺失後確認**：再填一筆 →「檢查這筆」→ 按「確認寫入帳本」後馬上關掉分頁（請求已送出、回應收不到）→ 重開 `http://localhost:8765/#/record` → 應出現「上次送出的這筆還沒確認結果」，「檢查這筆」不能按 → 按「用原編號確認寫入結果」→ 顯示「這筆之前已經寫入過…」或「✓ 已寫入…」都可以，重點是**測試帳本只多一列**。
4. **沒送到**：填一筆 →「檢查這筆」→ 出現確認畫面後，瀏覽器開發者工具（F12）→「Network」把連線改成「Offline」→ 按「確認寫入帳本」→ 連不上，出現「上次送出的這筆還沒確認結果」→ 改回「No throttling」→「用原編號確認寫入結果」→ 這次才寫入，只多一列。
5. **放棄**：做一次第 3 步，到確認框時按「放棄」→ 確認框消失、帳本沒變，可以記新的一筆。
6. **重送不重複**（可略過）：第 2 步寫入後，開發者工具「Network」找到那個 POST，右鍵「Replay XHR／重新傳送」→ 回應有 `"repeated":true`，帳本沒多一列。
7. **每月定投金額**：改一個金額 →「確定」→ 測試帳本「定投金額」多一列（下個月生效）；測完在副本刪掉這一列。
8. 測完：本機記帳頁「⚙ 記帳連線」→「清除」；副本的 Apps Script「部署」→「管理部署作業」→ 封存測試部署（或直接把副本丟到垃圾桶）。

同編號不同內容、兩個請求同時到，這兩種從網站畫面做不出來，由本機測試頁涵蓋。

### 驗證完：更新正式帳本的 Apps Script

1. 開正式「投資共用帳本」→「擴充功能」→「Apps Script」→ `程式碼.gs` 全選貼上新版 → 儲存。
2.「部署」→「管理部署作業」→ 選現有的網頁應用程式部署 → 鉛筆（編輯）→「版本」選「新版本」→ 說明寫「R02 鎖內查重」→「部署」。**不要用「新增部署作業」**（會產生新網址，網站各裝置都要重貼）。網址不變，網站不用改。
3. 網站「記帳」頁 →「測試連線」看到「✓ 連線成功」就好（`ping` 不寫入），不用為了驗證多記一筆。
4. 要退回：同一個地方「編輯」→「版本」選前一版 →「部署」。

## 網站的警告視窗（2026-11-05 使用者要求）

- 買進：Apps Script 試算後，如果這個月在這筆之前已經投入（達當月定投金額 9 成），先跳視窗問這筆是「自主加碼」還是「其他規劃」（要寫一句說明，有「提前投入下個月的定投」「同一筆定投分次成交」「補偏低的一檔（再平衡）」可以點），選擇寫在備註開頭；按「關閉視窗」這筆就不記。不管選哪一種，超過定投的金額都算自主加碼，不影響下個月的定投。
- 賣出：送出前先跳視窗，顯示第一次買進台股到今天幾天、台股累計買進、配置紀律連續投入幾個月，勸使用者照計畫投入；預設按鈕是「我再想想，不賣了」，「我確定要賣出」要等 5 秒才能按。

## 動作

| 動作 | 內容 |
|---|---|
| `ping` | 測試連線，回傳帳本名稱、本月與下個月的定投金額，不寫入 |
| `addTrade` | 「交易紀錄」加一列（日期、市場＝台股、代號（文字，保留前導 0）、買賣、股數、成交價、TWD、手續費、交割金額、台幣金額＝交割金額、計入資金池＝是、台幣金額來源＝網站輸入、備註、成交時間、交易稅），再更新「持倉」：買進加股數與成本；賣出照平均成本扣，股數不夠就拒絕；沒有的代號新增一列（複製上一列的公式）。確認日只往後更新，來源欄尾端記「網站輸入：日期 買賣 股數」 |
| `setMonthly` | 「定投金額」分頁：下個月的列已存在就改金額，沒有就新增一列（複製上一列的公式）。分頁裡已經有更晚月份的列時拒絕，請到試算表手動調整 |

檢查規則：日期不能是未來；代號 4～6 碼數字可帶一個英文字母；股數正整數；成交價金是整數，和股數 × 成交價差不超過 1 元或 0.1%；手續費必填（可以是 0）；交易稅選填（預設 0）。交割金額：買進＝價金＋手續費＋交易稅，賣出＝價金−手續費−交易稅。

## 帳本配合的改動（2026-11-05 已做）

- 「交易紀錄」O 欄「成交時間」、P 欄「交易稅」。排程讀 `A1:N`、`engine/discipline.py` 與網站都用表頭名稱讀，不受影響。
- 新分頁「定投金額」（gid 10）：生效月份、每月定投（NT$）、設定日期、備註，E、F 欄是公式（這段期間入金次數、入金合計）。第 2 列是初始值 2026-11 起 3,000。
- 「設定」分頁：每月入金（B7）改成公式＝本月的定投金額；第 11 列「記帳前錢包零頭 80」；第 18 列「累計入金」＝定投金額分頁 F 欄加總；第 19 列「下月定投」；可用資金（B15）＝B6＋B11＋B18−B13＋B14。

## 第一次設定（使用者做，約 5 分鐘）

1. 開「投資共用帳本」試算表 → 上方選單「擴充功能」→「Apps Script」。
2. 左邊「程式碼.gs」（Code.gs）：全選刪掉，貼上 repo 的 [`apps_script/ledger_write.gs`](../apps_script/ledger_write.gs) 全部內容 → 按儲存（磁碟圖示）。專案名稱可以改成「帳本寫入」。
3. 產生密鑰：手機或電腦打開網站「記帳」頁 →「⚙ 記帳連線」→「產生密鑰」，複製那串字（也可以自己想一串 20 個字元以上）。
4. Apps Script 左邊齒輪「專案設定」→ 最下面「指令碼屬性」→「新增指令碼屬性」：屬性 `WRITE_KEY`，值貼上剛才的密鑰 → 儲存。
5. 右上「部署」→「新增部署作業」→ 齒輪選「網頁應用程式」→ 說明隨意、「執行身分」選「我」、「誰可以存取」選「所有人」→「部署」。
6. 第一次會要求授權：選自己的 Google 帳號 → 出現「Google 尚未驗證這個應用程式」是因為這是你自己寫的程式，按「進階」→「前往『帳本寫入』（不安全）」→「允許」（權限是讀寫你的試算表）。
7. 複製「網頁應用程式」網址（`https://script.google.com/macros/s/…/exec`）。
8. 回網站「記帳」頁 →「⚙ 記帳連線」貼上網址（密鑰欄已經有剛才產生的）→「儲存並測試」，看到「✓ 連線成功：『投資共用帳本』」就完成。其他裝置（手機）要各自貼網址與同一個密鑰。

注意：網址＋密鑰等於帳本的寫入權限，不要貼到別的地方。懷疑外流時，到指令碼屬性換一組新的 `WRITE_KEY`，再到網站各裝置更換。
