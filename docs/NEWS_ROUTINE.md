## 1. 為什麼要獨立一個排程

- 10/22 美股晨報的新聞只做了 9 次搜尋：CNBC 讀不到、多是二手網站，NVDA、AAPL、Fed 幾乎沒有查。兩個晨報各自做大範圍搜尋，重複又不完整。
- reuters.com 直接讀回 401，但 Google News RSS 一天有約 100 則 Reuters 標題 → 由第一層用程式抓標題，第二層只負責挑重點、找得到的原文查證、判斷影響。
- 晨報（第三層）只讀整理好的列，保留各自的事件旗標規則，搜尋次數可以大幅減少。

## 4. 流程

1. 下載 repo 資料；`headlines.json` 的產生時間必須是今天 07:30 以後，否則改用退路（第 7 節）。
2. 用 python 篩出時間窗內的標題（台北前一個平日 08:40 到現在；週一從上週五 08:40 起），對應到標的：美股六檔、台股三檔（含 2330 與兩檔主動 ETF 的前十大成分股）、總經。同一事件多家報導合併成一件，保留等級最高的來源，其他列在「來源」。
3. 挑重點：每個標的最多 3 件、總經最多 5 件；優先 Tier 1～2、時間最近、可能影響旗標的（財報與財測、監管與反壟斷、出口管制、關稅、Fed 決策、重大事故、合併）。其中最多 8 件找原文查證，查不到就標「僅標題」，不補造細節。
4. 社群與情緒：Truth Social、X、CMoney、口袋晨報、CNN 恐懼貪婪、台指 VIX。
5. 每件事件寫：一句事實（含數字與日期）、影響（偏多／偏空／中性）、建議旗標與理由（第 6 節）。
6. 用 python 產生所有列（`news_rows.json`），用一次 `append_values` 全部寫入，不分批、不手打（10/22 美股晨報分批手打曾多寫一列）。
7. 用 SendUserMessage 傳摘要（第 5.2 節）。

## 5. 輸出

### 5.1 「新聞」分頁（測試版「測試_新聞」），一件事件影響幾個標的就寫幾列

| 欄 | 內容 |
|---|---|
| A 產生時間 | 台北時間 ISO（同一次執行相同） |
| B 資料日 | 台北今天（晨報用它找當天的列） |
| C 類別 | 摘要／公司／產業／政策／總經／地緣／社群／情緒 |
| D 市場 | us／tw／macro |
| E 標的 | VOO、GOOGL、NVDA、TSLA、SPCX、AAPL、009816、00981A、00411A，或「總經」「市場」；同學風向列另有 2330 |
| F 事件ID | `YYYYMMDD-NN`，同一事件的多列相同 |
| G 事件時間 | 台北時間 |
| H 來源 | 主要來源（其他來源用「、」接在後面） |
| I 等級 | 1～4 |
| J 查證 | 已查證／僅標題／無法查證 |
| K 原文網址 | 查證用的網址（沒有就放標題連結） |
| L 事實 | 一句話，含數字與日期 |
| M 影響 | 偏多／偏空／中性 |
| N 建議旗標 | none／block／boost |
| O 理由 | 為什麼是這個旗標（引用等級與查證狀態） |
| P 其他相關標的 | 例如成分股 2330、ARKX |

- 第一列是「摘要」：輸入狀態（headlines 產生時間與則數、Fed、Gmail、CMoney 是否取得）、各標的件數、WebFetch／WebSearch 次數、開始與結束時間。
- 沒有相關消息的標的也寫一列「無重大消息」，晨報才分得出「沒消息」和「排程沒跑」。
- CMoney 同學風向（使用者 2026-10-22 決定改由本排程讀）：2330、009816、00981A、00411A 各一列，類別「情緒」、市場 tw，事實寫「同學風向 51 分「中立」（更新 10/19 14:00）」或「樣本不足（累積中）」「未取得」。台股晨報第三層改讀這四列。
- 同一資料日重跑會多一組列；晨報取同一資料日「產生時間」最新的那組。

### 5.2 推播

- 正式版（使用者 2026-10-22 決定）：**只在有任何建議旗標不是 none，或有 Tier 1（官方）重大事件時推播**：SendUserMessage 傳 10 行以內的摘要（非 none 的事件、Tier 1 重大事件、寫入結果），再用 PushNotification 送一行重點。其他日子只寫試算表，不呼叫 SendUserMessage 或 PushNotification，最後的回覆只寫一行「已寫入 N 列，無需推播」。
  - Tier 1 重大事件指：Fed 利率決策或主席聲明、政府正式公告的關稅或出口管制、監測標的或主要成分股的財報、財測或重大公告、SEC 文件揭露的重大事項。
  - 排程本身也有完成通知設定（email、push）。建立正式排程時要確認關掉，否則每天仍會收到通知（建立時請使用者確認）。
- 測試版：傳完整的事件表與「測試檢查」，方便比對。

## 6. 建議旗標（只是建議，晨報依自己的規則決定）

- **block**：符合晨報 block 定義（美股：財測大幅下修、對 NVDA 的新出口限制確定實施、GOOGL 拆分或重大反壟斷處分確定、會計或治理醜聞、SpaceX／Tesla 重大事故並影響營運、美國市場系統性危機；台股：台積電或核心持股財測大幅下修、對台出口管制或高關稅確定實施、台海軍事衝突、ETF 策略或經理人重大變更、00411A 主要海外持股系統性崩跌），而且是 Tier 1，或 Tier 2 且已查證。
- **boost**：前一交易日的下跌主要由情緒性消息造成，且已有修復證據（盤後、期貨、台積電 ADR、發言被澄清）。08:40 還看不到台股盤中，所以台股的 boost 一律標「候選」，由台股晨報依盤中價決定。
- Tier 3 只能佐證；**Tier 4（分析師、社群、二手網站）不能單獨改變旗標**。拿不準就 none。

## 7. 失敗退路

| 狀況 | 做法 |
|---|---|
| headlines.json 下載失敗、過期或 `errors` 很多 | 改用 WebSearch 固定查詢（美股六檔一次、總經與 Fed 一次、台股與台積電一次），再查證；摘要列寫「標題清單未取得，改用搜尋」 |
| Fed、Gmail、CMoney 取不到 | 該項寫「未取得」，其他照常 |
| 原文查不到 | 「僅標題」，不補細節；不能據此給 block |
| 寫入試算表失敗 | 重試一次；仍失敗就一定推播（不受推播條件限制），附上 `news_rows.json` 的內容，晨報會走自己的退路 |
| 執行太久 | 09:10 還沒查證完就停止查證，先寫入已完成的部分（未查證的標「僅標題」） |
| 本排程整個沒跑 | 晨報在 09:20／10:17 找不到當天的列，就退回 2～3 個精簡搜尋（第三層的規則） |
