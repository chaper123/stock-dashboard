# 新聞與社群晨報（新聞三層架構的第二層）

> 2026-10-22 設計（同日使用者同意第 10 節三項），**尚未建立排程**。使用者 2026-10-22 決定新聞改三層架構（[PROGRESS.md](PROGRESS.md)「下一步」第 6 項）：① market-data 抓標題（phase-1-market-data 負責）→ ② 本排程查證並整理成結構化的列 → ③ 兩個晨報改讀這些列。本文件是 ②。

## 1. 為什麼要獨立一個排程

- 10/22 美股晨報的新聞只做了 9 次搜尋：CNBC 讀不到、多是二手網站，NVDA、AAPL、Fed 幾乎沒有查。兩個晨報各自做大範圍搜尋，重複又不完整。
- reuters.com 直接讀回 401，但 Google News RSS 一天有約 100 則 Reuters 標題 → 由第一層用程式抓標題，第二層只負責挑重點、找得到的原文查證、判斷影響。
- 晨報（第三層）只讀整理好的列，保留各自的事件旗標規則，搜尋次數可以大幅減少。

## 4. 流程

正式版（2026-10-28，`private/routines/news_morning.v2.prompt.md`，10,104 字）：
1. 下載 repo 資料與 `engine/news_select.py`（commit 寫死、核對 SHA-256）；`headlines.json` 的產生時間必須是今天 07:30 以後，否則改用退路（第 7 節）。
2. 讀「報告存檔」最後一列美股、台股的精簡 JSON（持有與買區）；讀不到就不加權。
3. `news_select.py --compact us_compact.json --compact tw_compact.json`（固定規則，模型不自己篩）：
   - 時間窗：台北前一個平日 08:40 到現在，週一從上週五 08:40 起。略過第一層標 `time_suspect` 的標題；第一層沒做時間檢查時，自己略過同來源 5 則以上發布時間完全相同的標題。
   - 對應標的：美股六檔、台股三檔（2330／TSM、00981A 前十大、00411A 前五大的 Tier 1～2）、總經。
   - 過濾：產品發表與評測、消費者抱怨、地方稅務或訴訟、電視節目片段等雜訊（`NOISE`，含監管、出口、關稅、財報等字眼的不算）；Tier 4 只在那個標的沒有其他消息時保留。
   - 加權：持有 +2、在買區 +2（兩者都有＝4）、總經 1；今晚的 FOMC、CPI 在有持有或買區時算 3。
   - 必寫事項（`must_cover`）：前一交易日大幅變動、已公布的財報（美股盤後時間過了才算）、台股休市、Fed 新聞稿。
   - 今晚／明早（`agenda`）：今晚到明天中午（台北）的監測標的財報、FOMC 決議、CPI。
   - 重點順序建議（`highlight_slots`）：P1＝持有或買區（排程事件 → 必寫 → 各標的最好的一則 Tier 1～2，同一件事只列一次，最多 4 則消息）；P2＝Fed 新聞稿或沒有持有資料時的總經排程；P3＝其他必寫事項。
4. 挑事件並查證：必寫事項與今晚／明早各寫成事件列；其他每個標的最多 2 件、總經最多 4 件，只寫 Tier 1～2、和買點邏輯有關的（Yahoo Finance 上的 Motley Fool、GuruFocus 等以原始來源算 Tier 4）。查證最多 10 件（重點 → 必寫 → 其他）。網址只用候選的 url 或搜尋結果，不可自己拼。查不到的只有 Tier 1～2 的必寫事項能寫「僅標題」，其他不寫；事件時間不在時間窗內的不寫（排程事件除外）。
5. 今天的重點：照順序挑最多 3 條，同一件事合併；只用已查證或排程事件；每條一句「事件 → 影響哪幾檔（持有／買區）→ 由哪個晨報依什麼重算」。
6. 社群與情緒：Truth Social、X、CMoney、口袋晨報（Gmail 配額錯誤時後段再試一次）、CNN 恐懼貪婪、台指 VIX。
7. 每件事件寫一句事實、影響、建議旗標與理由（第 6 節；必寫事項的理由要有「必寫」，網站用它認）；用 python 產生所有列（`news_rows.json`），一次 `append_values` 寫入，不分批、不手打。
8. 訊息（第 5.2 節）：最後的回覆一律放這份訊息；符合推播條件才 SendUserMessage＋PushNotification。

## 5. 輸出

### 5.1 「新聞」分頁（測試版「測試_新聞」），一件事件影響幾個標的就寫幾列

| 欄 | 內容 |
|---|---|
| A 產生時間 | 台北時間 ISO（同一次執行相同） |
| B 資料日 | 台北今天（晨報用它找當天的列） |
| C 類別 | 摘要／重點／公司／產業／政策／總經／地緣／社群／情緒 |
| D 市場 | us／tw／macro |
| E 標的 | VOO、GOOGL、NVDA、TSLA、SPCX、AAPL、009816、00981A、00411A，或「總經」「市場」；同學風向列另有 2330；重點列可以多檔，用逗號分隔 |
| F 事件ID | `YYYYMMDD-NN`，同一事件的多列相同 |
| G 事件時間 | 台北時間 |
| H 來源 | 主要來源（其他來源用「、」接在後面） |
| I 等級 | 1～4 |
| J 查證 | 已查證／僅標題／無法查證 |
| K 原文網址 | 已查證：實際讀到的網址；僅標題：候選的原文網址，沒有就空白（正式版起不放 Google News 轉址，也不可自己拼網址） |
| L 事實 | 一句話，含數字與日期 |
| M 影響 | 偏多／偏空／中性 |
| N 建議旗標 | none／block／boost |
| O 理由 | 為什麼是這個旗標（引用等級與查證狀態） |
| P 其他相關標的 | 例如成分股 2330、ARKX |

- 第一列是「摘要」：輸入狀態（headlines 產生時間與則數、Fed、Gmail、CMoney 是否取得）、各標的件數、WebFetch／WebSearch 次數、開始與結束時間。
- **重點列（正式版，2026-10-28；網站新聞頁與決策鏈讀這幾列）**：緊接在摘要列之後，最多 3 列，**列的順序就是重要性順序**。
  - C 類別「重點」；D 市場填受影響標的的市場（跨市場或總經填 macro）；E 標的填受影響的代號，多檔用逗號（例如 `009816,00981A`；總經事件填「總經」）。
  - F 事件ID 填對應事件列的 ID（排程事件也有一列事件，所以一定對得到）；G 事件時間、H 來源、I 等級、J 查證、K 原文網址、M 影響、N 建議旗標照對應的事件列。
  - L 事實是一句話：「事件（含關鍵數字或時間）→ 影響哪幾檔（持有／哪個買區）→ 接下來由哪個晨報依什麼重算」；O 理由寫對持有或買區的影響與重算的晨報；P 留空。
  - 只用已查證的事件或排程事件；沒有影響持有或買區的消息時用總經排程或大幅變動，都沒有就一列「今天沒有影響持有或買區標的的重大消息」。
- 沒有相關消息的標的也寫一列「無重大消息」，晨報才分得出「沒消息」和「排程沒跑」。
- CMoney 同學風向（使用者 2026-10-22 決定改由本排程讀）：2330、009816、00981A、00411A 各一列，類別「情緒」、市場 tw，事實寫「同學風向 51 分「中立」（更新 10/19 14:00）」或「樣本不足（累積中）」「未取得」。台股晨報第三層改讀這四列。
- **口袋恐懼貪婪（2026-10-28 加，網站情緒區的口袋儀表讀這一列，字樣要照寫）**：每天一列。類別「情緒」、市場 tw、標的固定「口袋恐懼貪婪」（網站靠它找列）、事件ID `YYYYMMDD-P1`、事件時間＝口袋晨報寄出時間（台北，例 `10-28 06:25`）、來源「口袋晨報（Gmail）」、等級 4、查證「已查證」、原文網址空白、事實「口袋恐懼貪婪 26 分「恐懼」（前一交易日 28 分；資料日 10/27）」、影響中性、建議旗標 none、理由「參考層」、其他相關標的 `009816,00981A,00411A`。網站解析：分數＝「恐懼貪婪 N 分」、評等＝第一個「」內的文字，另讀「前一交易日 N 分」與「資料日 M/D」。信中沒有前一交易日分數就寫「前一交易日 未提供」；取不到（例如 Gmail 配額錯誤、重試後仍失敗）時事實寫「未取得（原因）」，這一列照樣要寫。分數在讀口袋晨報全文時一起取。
- 同一資料日重跑會多一組列；晨報取同一資料日「產生時間」最新的那組。

### 5.2 推播

- 正式版推播條件（使用者 2026-10-22 決定，2026-10-28 沿用）：**只在有任何建議旗標不是 none、有 Tier 1（官方）重大事件，或寫入失敗時推播**（SendUserMessage＋PushNotification 一行重點）。其他日子不呼叫兩者；最後的回覆仍放同一份訊息，網站看得到明細。
  - Tier 1 重大事件指：Fed 利率決策或主席聲明、政府正式公告的關稅或出口管制、監測標的或主要成分股**已公布**的財報、財測或重大公告、SEC 文件揭露的重大事項。預定但還沒發生的排程事件不算。
  - 排程本身也有完成通知設定（email、push）。建立正式排程時要確認關掉，否則每天仍會收到通知（建立時請使用者確認）。
- 訊息排版（使用者 2026-10-28 同意，起因是 10/28 測試版「連閱讀都有困難，看不出重點」）：
  ```
  **新聞晨報｜YYYY/MM/DD**
  **今天的重點**
  1. 事件 → 影響哪幾檔（持有／買區）→ 由哪個晨報依什麼重算（最多 3 條）
  **旗標**：全部正常（沒有建議 block 或 boost）｜或每件一行：標的、事件、等級與查證、理由
  **情緒**：CNN 恐懼貪婪 N（標籤，前一日 N）｜台指 VIX N（MM/DD）
  **今晚／明早**：每件一行「台北時間｜事件｜影響的標的」，沒有就寫「無」
  各標的明細 → 網站「決策鏈 → 新聞」
  以上為新聞整理與建議旗標，不是投資建議；買賣訊號以兩個晨報為準。
  ```
  同一件事只寫一次並列出影響的標的；不逐欄攤開、不每行寫 none、不寫「同上」；口袋晨報或 Gmail 未取得只在摘要列註明。
- 測試版：傳完整的事件表與「測試檢查」，方便比對。

## 6. 建議旗標（只是建議，晨報依自己的規則決定）

- **block**：符合晨報 block 定義（美股：財測大幅下修、對 NVDA 的新出口限制確定實施、GOOGL 拆分或重大反壟斷處分確定、會計或治理醜聞、SpaceX／Tesla 重大事故並影響營運、美國市場系統性危機；台股：台積電或核心持股財測大幅下修、對台出口管制或高關稅確定實施、台海軍事衝突、ETF 策略或經理人重大變更、00411A 主要海外持股系統性崩跌），而且是 Tier 1，或 Tier 2 且已查證。
- **boost**：前一交易日的下跌主要由情緒性消息造成，且已有修復證據（盤後、期貨、台積電 ADR、發言被澄清）。08:40 還看不到台股盤中，所以台股的 boost 一律標「候選」，由台股晨報依盤中價決定。
- Tier 3 只能佐證；**Tier 4（分析師、社群、二手網站）不能單獨改變旗標**。拿不準就 none。

## 7. 失敗退路

| 狀況 | 做法 |
|---|---|
| headlines.json 下載失敗、過期或 `errors` 很多 | 改用 WebSearch 固定查詢（美股六檔一次、總經與 Fed 一次、台股與台積電一次），再查證；摘要列寫「標題清單未取得，改用搜尋」 |
| Fed、Gmail、CMoney 取不到 | 該項寫「未取得」，其他照常；Gmail 回配額錯誤（Resource has been exhausted）先做其他步驟，產生列之前再試一次 |
| 「報告存檔」讀不到（持有與買區） | 不給 `--compact`，重點不加權（程式退回總經排程 → 必寫事項的順序），摘要列註明 |
| 原文查不到 | Tier 1～2 的必寫事項標「僅標題」，其他不寫；不補細節；不能據此給 block |
| 寫入試算表失敗 | 重試一次；仍失敗就一定推播（不受推播條件限制），附上 `news_rows.json` 的內容，晨報會走自己的退路 |
| 執行太久 | 09:10 還沒查證完就停止查證，先寫入已完成的部分（未查證的標「僅標題」） |
| 本排程整個沒跑 | 晨報在 09:20／10:17 找不到當天的列，就退回 2～3 個精簡搜尋（第三層的規則） |
