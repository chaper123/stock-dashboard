## 計算（新檔 `site/js/backtest.js`，純函式，加進 `sw.js` 的 `SHELL_FILES`）

1. **月報酬**：取每個月最後一個交易日的收盤，相鄰兩個月底相除減 1。資料最後一天所在的月份還沒結束，不用；第一筆從 2003-01 月底到 2003-02 月底。
2. **模擬**：`value = value × (1 + r) + pmt`，每月一次，月底投入（跟現有 `fv` 的時間點一樣）。起點是 `pv`。回傳每個月底的值。
3. **歷史上真的發生過（滾動區間）**：每一個能湊滿 `months` 個連續月報酬的起點各跑一次模擬，取期末值。回傳個數、最差、中位數、最好，以及最差與最好各從哪個年月開始。個數不到 24 個要標「樣本太少」（20 年大約只有 46 個起點，而且彼此高度重疊）。
4. **抽樣推估（區塊抽樣）**：
   - 一條路徑：重複「隨機挑一個起點，取連續 12 個月的月報酬（超過結尾就接回開頭）」，湊滿 `months` 個月後截斷，再跑模擬。
   - 2,000 條路徑。亂數用固定種子的 mulberry32（種子寫成具名常數），同樣的輸入每次算出來都一樣。
   - 輸出：期末值的第 10、50、90 百分位；每一年年底的這三個百分位（畫圖用）；期末值低於投入本金（`pv + pmt × months`）的路徑比例。
   - 百分位的定義：由小到大排序，位置 `p × (n − 1)`，落在兩個值之間就線性內插。
5. **回測期間的描述**：月報酬的起訖年月、這段期間的年化報酬、最大回落（月底資料算）。

### 計算（加在 `site/js/backtest.js`，純函式）

1. **N 年內要達標，每月要投多少**：同一條路徑上，期末值對每月投入是線性的：期末 ＝ `pv × G ＋ pmt × A`（`G` 是這條路徑的累積成長倍數，`A` 是每月投 1 元累積到期末的金額）。所以每條路徑需要的每月投入 ＝ `max(0, (目標 − pv × G) ÷ A)`，直接算、不用試誤。2,000 條路徑取第 10、50、90 百分位：第 10 是偏好的情況（投得少就夠）、第 90 是偏差的情況（要投更多）。目標用 N 年後的金額（有通膨時照現有的 `needAt`）。
2. **照現在的每月投入，N 年內達標的機率**：期末值大於等於目標的路徑比例。
3. **多久存到目標**：每條路徑照現在的每月投入一個月一個月往下跑（區塊不夠就繼續抽），到資產大於等於「當月的目標」為止；有通膨時目標每個月跟著長（年通膨換成月的）。上限 100 年（1,200 個月），到上限還沒達標就記成「100 年以上」。取第 10、50、90 百分位：第 10 是偏好的情況（比較快）、第 90 是偏差的情況（比較慢）。
4. 亂數：同一個固定種子；每一項計算各自從種子重新開始，結果才不會互相影響、也能重現。
5. N 年不超過歷史長度而且滾動起點有 24 個以上時，另外列「歷史上真的發生過」：每個起點實際需要的每月投入的最差、中位數、最好（含起始年月）。多久存到不做滾動（後面的資料會不夠）。

### 計算（加在 `site/js/backtest.js`，純函式）

記號：存錢月數 `S = (退休 − 現在) × 12`、提領月數 `D = (壽命 − 退休) × 12`、總月數 `N = S + D`（最多 82 年、984 個月）；月通膨 `m = (1 + 年通膨)^(1/12) − 1`；第 t 個月（1～N）的通膨倍數 `f_t = (1 + m)^t`。

1. **路徑**：跟 `pathGrowth` 一樣從固定種子重新開始，依序用 `blockPath(returns, N, rng)` 產生 2,000 條長度 N 的路徑。下面兩個函式各自從種子重新開始，所以拿到的是同一組路徑。
2. **月底公式**（時間點跟第一部分一樣都在月底）：存錢期（t ≤ S）`value = value × (1 + r) + pmt`；提領期（t > S）`value = value × (1 + r) − W × f_t`，`W` 是用今天的錢表示的每月花費（所以花費每月跟著通膨長）。
3. **每月可花多少（`lifecycleSpend`）**：每條路徑一個月一個月往下算三個量——
   - `g = g × (1 + r)`：整段的累積倍數 `G`；
   - `a = a × (1 + r) + (t ≤ S ? 1 : 0)`：存錢期每月投 1 元，累積到第 N 個月的 `A`；
   - `b = b × (1 + r) + (t > S ? f_t : 0)`：提領期每月領「今天的 1 元」，累積到第 N 個月的 `B`；
   - 另外記下第 S 個月月底的資產（名目）`pv × g_S + pmt × a_S`，當「退休時資產」。
   - 第 N 個月的資產 ＝ `pv × G ＋ pmt × A − W × B`，對 `W` 是線性的，所以剛好花到預期壽命用完的每月花費 `W* = max(0, (pv × G + pmt × A) ÷ B)`，直接算、不用試誤。
   - 提領期沒有投入，資產一旦小於 0 之後只會更小，所以「第 N 個月 ≥ 0」等於「中途從來沒用完」，`W*` 就是這條路徑不會用完的最高花費。
   - 回傳：退休時資產（換成今天的錢：除以 `f_S`）與 `W*` 各自的第 10、50、90 百分位；每條路徑的 `W*`（`Float64Array`，測試與核對用）；路徑數。
4. **照某個花費跑一遍（`lifecycleRun`，多一個參數 `W`）**：同一組路徑照月底公式模擬。
   - 某個月算完小於 0 就記為「第 t 個月用完」，之後這條路徑的資產當 0、不再提領。
   - 錢撐到預期壽命的機率 ＝ 沒有用完的路徑比例。
   - 用完的月份取第 10、50 百分位（沒用完的路徑當成無限大）；內插用到沒用完的路徑時記成 `null`。
   - 每一年年底（第 0、12、24…N 個月）的資產（用完後是 0）換成今天的錢（除以 `f_t`）的第 10、50、90 百分位，畫圖用；第 0 年就是 `pv`。
5. 百分位、種子、區塊長度、路徑數都沿用第一部分的常數與 `percentiles`，不另外定。
6. 不做滾動區間：一輩子的長度遠超過約 23.8 年的歷史，只有抽樣推估。

### 驗收

- `tests/web/backtest.html` 補測試：
  - 每月報酬都相同（r ≠ 0）、通膨 0：退休時資產等於現有 `fv` 的結果（同一個月報酬）；`W*` 等於「退休時資產 × r ÷ (1 − (1 + r)^−D)」；三個百分位相同。
  - 有通膨、報酬固定：`lifecycleRun` 照 `W*` 的 0.99 倍跑，撐到的機率 100%；1.01 倍是 0%。
  - 同一組路徑：`lifecycleRun` 撐到的比例等於 `W*` ≥ W 的路徑比例；`lifecycleRun` 第 S ÷ 12 年的百分位等於 `lifecycleSpend` 的退休時資產。
  - 用完後資產記 0、不會再變正；用完月份的百分位內插碰到沒用完的路徑時是 `null`。
  - 今天的錢換算：通膨 i 時第 y 年的值是名目值除以 (1 + i)^y。
  - 固定種子可重現；年齡不合理時不算。
- 用 Python 照同樣的亂數順序另外算預設值的 `W*` 三個百分位、照中間值花費的撐到機率，差距在 0.1% 以內。
- 本機預覽真實資料：預設年齡與另一組年齡（例如 40／60／90）各看一次；重新整理後年齡還在；其他卡的數字跟改之前一樣（「N 年後」只多了第四部分的拆分）；桌面與 375 寬不橫向捲動、console 沒有錯誤；既有測試頁仍然通過。
- 回報預設值下的：退休時資產三個百分位、每月可花三個百分位、照中間值花費的撐到機率與用完年齡、Python 核對結果。
