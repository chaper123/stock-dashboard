> 這頁是擇時分析，只當參考，跟每月 80／20 定投的核心規則分開。討論與決定的經過在 [INSIGHTS.md](INSIGHTS.md) 5.2。

## 2. 第二版的決定（使用者 2026-11-12）

1. 候選範圍：台股掛牌 ETF，只要台股股票型與海外股票型，上市滿一年，近三個月日均成交金額最大的 30 檔，每月重排。
2. 分散型：整體連動、下跌日連動兩個數字都列，預設照整體連動由低到高，可以點欄位改排序。
3. 進攻型：照這一段自高點的跌幅由深到淺。
4. 頁面照條件排名，每一檔寫理由與代價，不寫「買哪一檔」。

## 3. 資料（market-data 新增，`candidates.py`）

現有流程照 `twwatch.py`（`openapi_latest`、`official_daily`）、`common.py`（`finmind`、`twse_openapi`、`finalize`、`write_csv`、`mark_failed`）、`fetch.py` 的 `PHASE1_STEPS`；測試照 `tests/test_twwatch.py`（假資料、不連網）。

### 3.1 候選名單

- 清單來源：證交所 OpenAPI `opendata/t187ap47_L`（基金基本資料彙總表：基金代號、基金類型、是否包含國外成分股、上市日期）。**只有上市**；上櫃 ETF 不列入（多為債券，櫃買 OpenAPI 本機回 403）。
- 類別（字串以 API 實際內容為準）：
  - `tw`：基金類型含「國內成分」，而且是「指數股票型基金」或「主動式…（股票）」。
  - `overseas`：基金類型含「國外成分」，而且是「指數股票型基金」或「主動式…（股票）」。
- 排除（任一成立）：代號尾碼 B、L、R、U、K、C、T、D；基金類型含 槓桿、反向、期貨、平衡、債券、連結、境外、外幣；名稱含 黃金、白銀、原油、石油、不動產、REIT、債。排除的每一檔連同原因寫進 `universe.json` 的 `excluded`，讓人檢查有沒有誤殺或漏網。
- 上市滿一年：上市日期在排名日往前 365 天以前。
- 排名：近 60 個交易日的日均成交金額（元），取前 30。
  - 平常：每天把 `STOCK_DAY_ALL` 的 `TradeValue` 存進 `data/candidates/turnover.csv`（`date,code,value`，只存符合資格的 ETF，保留最近 90 個交易日）。這支 API `twwatch.openapi_latest` 本來就會打，同一次回應重用，不要多打一次。
  - 第一次（還沒有累積資料）：用 FinMind `TaiwanStockPrice` 補近 60 個交易日，每檔一次請求。**先用一檔確認成交金額的欄位名稱與單位**；每次請求之間間隔，一個小時內不超過 250 次（未註冊約每小時 300 次，現有流程也在用）。
  - 累積不到 60 天時用現有天數（至少 5 天），`universe.json` 的 `window_days` 寫實際天數。
- 重排時機：每月第一個交易日，或 `universe.json` 不存在時。新進的補歷史；退出的檔案保留不刪、不再更新。

### 3.2 日線與合併檔

- 每檔 `data/candidates/<代號>_norm.csv`，格式同 `data/tw/<代號>_norm.csv`（無表頭：`date,volume,open,high,low,close`），至少 15 個月。代號已經在 `config.json` 的 `tw`／`tw_watch` 清單裡的不重抓，沿用 `data/tw/` 的檔。
- 合併檔 `data/candidates/closes.csv` 給網站一次讀完：第一列表頭 `date,<代號1>,<代號2>…`，每列一個交易日的收盤，沒有資料留空，只放最近 300 個交易日。
- `data/candidates/universe.json`：

  ```json
  { "generated_at_taipei": "2026-11-12 06:15", "ranked_on": "2026-11-03", "window_days": 60,
    "rule": "上市 ETF、台股與海外股票型、上市滿一年、日均成交金額前 30",
    "source": "證交所 OpenAPI（名單、成交金額）；日線 FinMind＋證交所 OpenAPI",
    "items": [{ "code": "0050", "name": "元大台灣50", "category": "tw", "listed": "2003-06-30", "avg_value": 12345678901, "rank": 1 }],
    "excluded": [{ "code": "00679B", "name": "…", "reason": "尾碼 B" }] }
  ```
- `meta.json` 加 `candidates/universe`（status、last＝ranked_on、items 數）與 `candidates/closes`（status、rows、first、last）。抓失敗照 `mark_failed`：保留舊檔、標 stale 或 fail，不影響其他資料集。
- README 補這三個檔的欄位說明與出處。

### 3.3 已知限制（頁面與 README 都要寫）

- 價格沒有還原配息與分割：分割由網站濾掉（4.1）；配息沒有加回，高股息 ETF 的跌幅會被除息放大。
- FinMind 的條款只寫「教育、非商業用途」，market-data 的 README 原本就把「放公開 repo 是否可行」列為待使用者決定；這一版把代號從 8 檔左右擴大到約 38 檔。**push 之前要有使用者的決定**（第 7 節）。

## 4. 計算（網站，`site/js/opportunity.js` 新增純函式）

### 4.1 報酬

- 行事曆＝`closes.csv` 的日期。`r_t = c_t ÷ c_{t−1} − 1`，只在連續兩個交易日都有收盤時才有值。
- `|r_t| > 30%` 視為分割或資料異常：那一天不算，代號記下來，頁面註腳列出。
- 還原序列：把濾過的報酬連乘（起點 1），跌幅與一年漲跌都用它算。
- 現有組合的日報酬 `r_p = 0.8 × r_009816 + 0.2 × r_00981A`（兩檔都有值的日子；比例取 `config.js` 的 `DISCIPLINE.target`）。兩檔的日線用既有的 `data/tw/`。

### 4.2 視窗與指標

- 視窗：最近 250 個交易日內，組合與該候選都有報酬的日子，天數 `n`。009816 在 2026-02-03 上市，所以目前 `n` 最多約 190；頁面寫實際天數。
- 整體連動 `corr`：`r_p` 與候選報酬的皮爾森相關係數。`n < 120` 是「資料不足」。
- 下跌日連動 `downCorr`：只取 `r_p < 0` 的日子再算一次相關係數，天數 `nDown`；`nDown < 40` 是「資料不足」。同時給 `downAvg`（那些日子候選的平均漲跌）與 `downAvgP`（組合自己的平均）。
- 這一段跌幅（進攻型用）：區間起點＝加權指數這一段高點的日期（`currentEpisode(ix).peak.date`）。用還原序列算 `episodeDd`（區間內最高到其後最低的最大跌幅）、`nowDd`（現在離區間內最高）、`rebound`（從區間最低點到現在）。區間不到 5 個交易日（大盤在高點附近）時進攻型不排名，顯示說明。
- 其他：年化波動 `vol = 標準差(r) × √252`（視窗內）、近一年漲跌 `ret`（還原序列，視窗內）、日均成交金額（`universe.json`）。

### 4.3 排名與判讀句

- 排除現有兩檔（它們放在表格最上面當對照列）。
- 分散型：`corr` 由低到高，資料不足的排最後。進攻型：`episodeDd` 由深到淺。
- 判讀句照固定規則產生，只寫事實、理由與代價：
  - `corr ≥ 0.8`：「和現有持股幾乎同步，分散效果有限」；`0.5～0.8`：「部分同步」；`< 0.5`：「連動低」。
  - 海外：「多一層匯率；美股收盤比台股晚，用日資料算的連動會偏低」。
  - 日均成交金額 `< 1 億元`：「成交量小，買賣價差可能較大」。
  - 進攻型一律加：「跌得深不代表會彈得多；連動高等於加碼同一個風險」。

### 4.4 測試（加進 `tests/web/opportunity.html`）

用自己造的序列：報酬只算連續交易日、30% 門檻濾掉分割、相關係數對已知答案（完全同步 1、完全相反 −1、手算一組）、下跌日只取 `r_p < 0`、資料不足的門檻、`episodeDd`／`nowDd`／`rebound` 對手算、排名把資料不足排最後、現有兩檔不進排名。

## 5. 頁面（`site/js/pages/opportunity.js`）

- 在「三種做法」後面、「加碼試算」前面加一張卡「新標的候選（照條件排名，不是建議）」。「積極」那一欄的「還沒做」改成指到這張卡。
- 卡片最上面寫：名單規則、排名日期、用了幾個交易日、資料到哪一天（資料狀態照 R14 的 `statusLine`）。
- 兩個清單並排（手機上下排）：分散型前 5、進攻型前 5，每檔一行數字加一句判讀。
- 「看全部」收合表格，欄位：代號與名稱、類別、整體連動、下跌日連動、組合下跌日的平均漲跌、這一段跌幅、現在離高點、近一年漲跌、年化波動、日均成交金額。點欄位標題排序。表格不折行、放在 `.table-wrap` 裡左右滑。
- 候選資料讀不到或還沒有時，這張卡顯示「候選資料還沒有」，其他區塊照常。
- 文字一律寫日期，不寫「今天」；不寫「建議」「應該買」。

## 7. 順序與分工

1. market-data：實作 3、跑測試、在本機產生一次資料、commit（**不 push**）。
2. 高階模型看名單與 diff；使用者決定 FinMind 資料放哪裡之後才 push。
3. 網站：實作 4、5 與測試，本機預覽。
4. 高階模型審查、使用者看過後合併；部署交給較便宜的模型。
